Summary of character based output streams 
1. A PrintStream is binary stream, which means, it writes binary data to its destination (which is the console in case ofSystem.out). So, whenever you use its printXXX methods, it converts the input into bytes using the given encoding or thecharset, or the default charset if not specified.2. Unlike other I/O stream classes, methods of PrintStream do not throw any checked exception.3. InputStreamReader and OutputStreamWriter are bridge stream classes that convert a binary stream into acharacter stream (or vice-versa) using the given or the default character encoding. These are created to be passed as constructorarguments while creating character streams such as BufferedReader and BufferedWriter.4. A PrintReader and PrintWriter are character stream classes but they can be created directly without using any bridgeclass object. They create a bridge stream internally.5. The int read(char[] buffer) of Reader class reads a number of characters that is equal to (or less than, if end offile is reached) to the size of the buffer array. If a lesser number of chars than the size of the array are read, then it is theprogrammers responsibility to clear up the rest of the elements in the buffer. If read is called after the end of file has beenreached, it returns -1. Therefore, standard practice is to read chars in a loop: while( (count =reader.read(buffer)) != -1 ){  } 6. The void write(char[] buffer) of Writer class writes all of the characters in the buffer to the output file. To avoidwriting junk characters from the previous read to the file, void write(char[] buffer, int off, int len) isused. E.g. write(buffer, 0, count).

7.3 Working with files ☝
Using java.io.File class
1. Absolute path starts with the root component, i.e., c:\ in windows and / on Unix. Relative path does not start with a rootcomponent. 2. To open a file, the absolute path to the file is required. If you open a file using a relative path, it is resolved against the currentdirectory to get the absolute path of the file.3. A canonical path is an absolute path that doesn't contain any redundant path fragments. E.g., c:\temp\a\..\test.txt isan absolute path but is not canonical. c:\temp\a\test.txt is canonical.4. A file in a Java program could be a directory or a file. It is represented by a java.io.File object. E.g. newFile("c:\\temp\\test2.txt"); Important methods of this class - boolean renameTo(File), boolean delete(), String[] list(), StringgetAbsolutePath(), and String getCanonicalPath().5. The File class contains two public static constants - 1. char separatorChar - It is the system-dependent default name-separator character. On Windows it is back slash ('\\') and on Linux, it is forward slash ('/'). 2. String separator: AString version of separatorChar for convenience. It contains the same character as separatorChar. To write temp/a in aplatform independent manner, use "temp"+File.separator+"a".6. The File class lets you enquire about its properties of the file through methods such as isDirectory(), isFile(),isHidden(), and lastModified().

7.4 Serialization ☝
Java Serialization is readymade mechanism available in the standard Java library for capturing the state of an object in a binary formthat can be saved to a file and can be used later to recreate that object containing the same state.
1. To be able to serialize and deserialize objects of a class, that class or any of its super classes must implementjava.io.Serializable interface. It is a marker interface and has no method or field.2. All primitives are serializable and most of the commonly used classes from the Java SDK such as String and wrapper classes(Integer, Double, etc.) implement Serializable. Arrays of primitives and of serializable objects are serializable too.3. Only instance fields are serialized. To ignore an instance field from serialization, mark that field as transient. 4. Constructors and instance initializers of a serializable class are not executed when an object of that class is created throughdeserialization. There are two exceptions to this rule: 1. If a serializable class extends a non-serializable class then the no-args constructor (and instance initializers) of the non-serializable super class will be executed. This means that a non-serializable super class of a serializable class must have ano-args constructor. 2. The canonical constructor of a record is invoked even when it is being created by deserializing the record data. 5. Using serialVersionUID : The Java serialization mechanism creates a version number for a every serializable class based onthe properties of that class. It includes this version number in the serialized stream. It is stored in an implicitly defined staticfinal int serialVersionUid field. Modifications to the class can potentially alter this value. While deserialization,the JVM compares the value of this field in the deserialized data with the one in the class. If the value is different, thendeserialization fails with a java.io.InvalidClassException.You can define this field explicitly to specify the value yourself. This is helpful when you want to modify the class but still wantto be able to deserialize the objects of the older version of the class to objects of the newer version of the class.6. The java.io.ObjectOutputStream and java.io.ObjectInputStream classes contain the logic of serializingand deserializing objects respectively. ObjectOutputStream's writeObject method takes a serializable object and converts itinto a stream of bytes. ObjectInputStream's readObject method reads a stream of bytes and creates the object back. Thesemethods too throw IOException. 7. A record too can be serialized if it implements Serializable but records are not allowed to customize their serializationand deserialization.8. Enums are always serializable.
Sample Code:

7.5 Using Console ☝
1. The java.io.Console class does not have any public constructor and so, you cannot create a Console object using new. 2. There is only one Console object for the entire Java application and you must acquire it by calling System.console().This method returns null if no console is associated with the JVM (it does not throw any exception).3. It has two methods to print text on the console:1. Console format(String format, Object... args) - Writes a formatted string to this console's outputstream using the specified format string and arguments. For example: the following code prints, Hi Bob, how are you?:Console c = System.console(); if(c!=null) c.format("Hi %s, how are you?", "Bob");2. Console printf(String format, Object... args) - This is a convenience method that works exactly thesame way as the format method. 
Since the above methods return the reference to a Console object, the calls can be chained. E.g. c.format("Hi!").printf("Good Morning! ").format("hello");4. It has 4 methods to read input from the console:1. String readLine() - Reads a single line of text from the console.2. String readLine(String fmt, Object... args) - Provides a formatted prompt, then reads a single line oftext from the console.3. char[] readPassword() - Reads a password or passphrase from the console with echoing disabled.4. char[] readPassword(String fmt, Object... args) - Provides a formatted prompt, then reads apassword or passphrase from the console with echoing disabled.5. Console's readPassword method does not encrypt the password. It just returns the string as typed by the user on the console.6. Console has a reader() method, which returns a Reader object and a writer() method, which returns aPrintWriter.
