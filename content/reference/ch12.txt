12.1 Detecting and creating a Locale ☝
1. A user's region (the word region and country are used interchangeably in this context) and language specific information iscaptured by the java.util.Locale class. It has several methods such as getCountry() and getLanguage() thatreturn specific details of the region that it represents. You are not expected to know the actual values that these methods returnfor any locale, but be aware that most of these methods return well defined codes. For example, they return "en" and "US" forlanguage and country if the Locale represents a region in the US that speaks English. 2. Language is a string of 2 to 8 letters in lowercase and country is a string of 2 or 3 letters in uppercase. 3. A Locale also captures a "category" that tells you whether this locale information is meant for customizing UI displays or forcustomizing textual output generated by the application. This category is represented by a static nested enum defined inLocale named Category. It has just two constants - DISPLAY and FORMAT. Whenever the category is not specified,FORMAT is assumed. 4. User's locale can be retrieved using the static methods getDefault() or getDefault(Locale.Category ) ofLocale. 5. User's default locale can be changed using Locale.setDefault(Locale newLocale) andLocale.setDefault(Locale.Category category, Locale newLocale). These methods change the defaultlocale of the JVM and any subsequent calls to getDefault will return the new locale.
Creating a Locale
1. A Locale object can be created using Locale.Builder or using overloaded static factory methods named of of theLocale class. 2. Locale's constructors are deprecated and can be ignored. Here are a few examples that you might see in the exam:
Locale enUs = new Locale.Builder().setLanguage("en").setRegion("US").build(); Locale hi = Locale.of("hi"); //language Hindi Locale hiIn = Locale.of("hi", "IN"); //language Hindi, country India
1. Observe that Builder's has a setRegion (and not setCountry) method but this API treats region and country as the same. 2. Locale also defines several public static constants for countries and languages for example, Locale.US andLocale.CHINESE. 3. A Locale object may not always have values for all of the details of the location that it represents. For example,Locale.CHINESE is a Locale that represents just the CHINESE language. Calling Locale.CHINESE.getCountry()will return an empty string (not null). Similarly, a calling getLanguage() on a Locale built using newLocale.Builder().setRegion("US").build() will return "". 4. Locale overrides the toString method to return a string representation of the Locale. As per JavaDoc, it returnslanguage + "_" + country + "_" + (variant + "_#" | "#") + script + "_" + extensions.Language is always lower case, country is always upper case, script is always title case, and extensions are always lower case.In the exam, you will see Locales that use only the language and the country and their string representations will be like en_USor fr_CA.5. Locale is an immutable class and has no setter methods.
12.2 Localizing Numbers and Dates ☝
Using NumberFormat
People in different regions are accustomed to seeing numbers formatted differently. The JDK provides an abstractclass java.text.NumberFormatter that can format a number as per the local standard. The following example shows how itcan be used:
int oneMillion = 1_000_000; Locale frFR = Locale.of("fr", "Fr"); Locale enUS = Locale.of("en", "US"); NumberFormat nfUs = NumberFormat.getCurrencyInstance(enUS); NumberFormat nfFr = NumberFormat.getCurrencyInstance(frFR); out.println("US:"+nfUs.format(oneMillion)); //prints US:$1,000,000.00 out.println("France:"+nfFr.format(oneMillion)); //prints France:1 000 000,00 € nfUs = NumberFormat.getPercentInstance(enUS); nfFr = NumberFormat.getPercentInstance(frFR); out.println("US:"+nfUs.format(0.1)); //prints US:10% out.println("France:"+nfFr.format(0.1)); //prints France:10 % NumberFormat nfC = NumberFormat.getCompactNumberInstance(); //get NumberFormat for the dSystem.out.println("Default Locale (Compact):"+nfC.format(oneMillion)); //prints Default nfC = NumberFormat.getCompactNumberInstance(enUS, NumberFormat.Style.SHORT); System.out.println("en_US (Compact):"+nfC.format(oneMillion)); //prints en_US (Compact):
The NumberFormat class has several static factory methods that can be used to create a NumberFormat instance. Most of themhave overloaded variants that take a Locale as an argument. The ones that do not take a Locale, return an instance that formats anumber according to the default locale. Note that the instances returned by these methods are not thread safe. 
The exam does not expect you to know the exact format in which numbers are printed for different locales but itdoes expect you to know the currency symbols for US Dollar($), Euro(€), and GB Pound(£).
Parsing NumbersA NumberFormat instance can also be used to parse a String containing a number written in locale specific manner. For example,nfC.parse("1M"), where nfC points to the same NumberFormat instance used in the above example, will return a Longcontaining the value 1000000. Be aware that the return type of the parse method is Number but it may actually return aDouble or a Long depending on whether the string has digits after decimal or not. Also remember that this method can potentiallythrow a java.text.ParseException, which is a checked exception.
Using DateTimeFormatter
To format the LocalDate/Time objects of the java.time package, you need to use thejava.time.format.DateTimeFormatter class. It has three different methods, ofLocalizedDate,ofLocalizedTime, and ofLocalizedDateTime, which can be used for formatting LocalDate, LocalTime, andLocalDateTime respectively. They require a FormatStyle argument. DateTimeFormatter also has a ofPattern method,which can format the LocalDate/Time objects for any given Locale. This method requires a FormatStyle and a Locale asarguments. For example:
DateTimeFormatter dfLocal = DateTimeFormatter.ofLocalizedDate(FormatStyle.SHORT); out.println(dfLocal.format(LocalDate.of(2024, 12, 1))); //prints 01/12/24 DateTimeFormatter dfFr = DateTimeFormatter.ofPattern("dd MMM uuuu", frFR); out.println(dfFr.format(LocalDate.now())); //prints 06 mai 2024
You are not expected to know the formats of various FormatStyle options for the exam.
JDK has a java.text.DateFormat class, which is similar to thejava.text.NumberFormat and can be used for format dates according the given Locale.However, since this class was created long before the new Date/Time API, it can only formatjava.util.Date objects. Unfortunately, it hasn't been enhanced to formatjava.time.LocalDate/Time objects.
Parsing Dates DateTimeFormatter has several methods that can parse a string into a LocalDate/Time objects. Technically, parsing dates is
mentioned in the objectives but parsing dates is quite complicated and we haven't seen anyone getting a question on this. If you havetime, you may go through the JavaDoc of the DateTimeFormatter class to learn more about this topic.
12.3 Localizing text
12.3.1 Internationalizing an app using ResourceBundle ☝
While developing an internationalized application, all user facing text or words used by the application are identified and listed infile along with their translations in the language that the development team knows in the form of name-value pairs. For example, let'ssay an application asks the user for their name and then prints that name with a greeting. Something like this:
public class HelloApp{ public static void main(String args){ Console c = System.console(); String name = c.readLine("What is your name? "); String greetings = "Hi"; System.out.println(greetings+" "+name); } } 
The application contains two user facing strings - "What is your name?" and "Hi". To internationalize this application,these two strings must not be hardcoded. Instead, the code must use keys to look up the the actual phrases at run time. This is done asfollows:
import java.util.ResourceBundle; public class HelloApp{ public static void main(String args){ ResourceBundle rb = ResourceBundle.getBundle("helloapp"); Console c = System.console(); String name = c.readLine(rb.getString("What is your name?")+" "); String greetings = rb.getString("Hi"); System.out.println(greetings+" "+name); } } 
There are several moving parts in the above code. I will explain all of them but let's get it to run first. If you compile and run it, youwill get an exception with the following message: java.util.MissingResourceException: Can't find bundle for base name helloapp, localeen_INYou may see a different locale name in the output because it depends on the locale of your machine. Now, create a file namedhelloapp.properties in the same folder that contains HelloApp.class with the following contents:
What\ is\ your\ name?=What is your name? Hi=Hi 
If you run it now, it will work as expected. The output isn't any different from the previous version but we have accomplished animportant thing in the above code. We have managed to look up the keys used in the program and show the resulting values to theuser. Although, it still prints messages in English, the application has now been internationalized! All we need to do now is tolocalize it for the locales in which we want to run this application. But before we do that, let me explain a few points about theabove code:
1. A ResourceBundle object contains locale-specific objects. Every resource bundle has a name and the program uses thatname to load the relevant files that contain locale specific entries. Once the entries in the files are loaded in the resourcebundle, the program can just lookup up a key in that resource bundle and use the returned locale specific value. A resourcebundle is not limited to containing just strings but for the purpose of the exam, we will stick to strings only.2. java.util.ResourceBundle is an abstract class but the JDK also provides a couple of concrete subclasses. One ofthose subclasses is PropertyResourceBundle, which can load key-value pairs from a properties file. However, insteadof directly instantiating the PropertyResourceBundle class, we use ResourceBundle's getBundle methodbecause this method is smart enough to figure out exactly which properties files are needed to create the desired resourcebundle based on the user's locale, which is what we want. The logic to determine the properties files needed to create a
resource bundle is important and I will explain it shortly, but in this example, since we don't have any locale specific propertiesfile, the getBundle method just loads a properties file with the same name as that of the resource bundle (but with extension.properties), i.e., helloapp.properties.3. The name of the resource bundle and the corresponding properties file follows the same convention as the one followed byclasses. Therefore, while locating a bundle named helloapp, the getBundle method expects helloapp.propertiesto be located directly on the classpath. If the name of the bundle were test.helloapp, thenhelloapp.properties would have to be present in the test folder and the test folder would have to be on theclasspath.4. The name of the keys in the properties file can be anything but the code must use the same key to loop up the value. Therefore, itis a common practice to use strings containing text that makes sense in the language that the dev team understands as keys. Usingkeys such as key1, key2, makes it hard to tie a key to the text that is meant to be shown to the user for that key.5. The backslashes (\) in the properties files are required to escape the space character.
12.3.2 Understanding Resource Bundles ☝
Resource bundles are hierarchical, meaning, a resource bundle always has a parent bundle unless the bundle is at the top of thehierarchy, in which case, it is called the "base bundle". The hierarchy of resource bundles is established using a set of resourcebundles whose names start with a common base name, such as helloapp used in the previous example. The remaining part of thename of a resource bundle is created using various attributes of a locale such as the language and the country separated byunderscores. These attributes must always be in the following order:
baseName + "_" + language + "_" + script + "_" + country + "_" + variant 
For the purpose of the exam, only the language and the country are important but script and variant behave similarly. So, for example,there can be a hierarchy of resource bundles with names helloapp, helloapp_fr, and helloapp_fr_CA, where the bundlenamed helloapp is at the top (grandparent) and the bundle named helloapp_fr_CA is at the bottom. Note that a bundle namedhelloapp_fr_FR will also be a part of this hierarchy but it will be on a new branch splitting from helloapp_fr. Similarly,the bundle named helloapp_en_UK will also be a separate branch splitting off of helloapp_en but if helloapp_en doesnot exist then helloapp_en_UK will be the immediate descendant of helloapp. This is illustrated in the following image: 
All of these resource bundles belong to the same family of resource bundles because they share the same base name, i.e., helloapp. 
Understanding the hierarchy of resource bundles is important because when a key is not found in a particular bundle, it isautomatically searched for in the parent bundle up to the base bundle. When a key is not found in any of the ancestor bundles either, aMissingResourceException is thrown. So, if helloapp_fr is queried for a key that it does not have, its parent bundle hellopapp will be checked and if helloapp too doesn't have that key then a MissingResourceException will bethrown. Note that the search for a key only propagates up the hierarchy and never to a child or a sibling.
So now, based on the above discussion, can you tell what resource bundle we should have if, for example, we want to localize ourapp for French speaking people in Canada? Right, hellopapp_fr_CA indeed. But remember that the values from this bundle willnot be used for French speaking people in France because their locale would be fr_FR and they would search for the keys inhelloapp_fr_FR. If you check the above graph, helloapp_fr_CA is a sibling and not a parent of helloapp_fr_FR.However, if we have resource bundle named helloapp_fr instead of helloapp_fr_CA, then the values from this bundle canbe used for all French speaking locales because helloapp_fr is a parent of helloapp_fr_CA as well ashelloapp_fr_FR.
12.3.3 Creating resource bundles using properties files ☝
The ResourceBundle class has several overloaded static getBundle methods out of which two are particularly important -getBundle(String baseName) and getBundle(String baseName, Locale locale). The former returns aResourceBundle for the user's default locale while the later returns a ResourceBundle for the given locale. ThebaseName is the common name of the all the resource bundles of a family as explained before.
Requesting a resource bundle for the default locale ☝
The getBundle methods automatically read a properties file whose name matches with the name of the requested resource bundle(provided the properties file is on the classpath) and create a PropertyResourceBundle instance that contains the entriesdefined in the properties file. So, for example, assuming that the user's default locale is en_US, the call toResourceBundle.getBundle("helloapp"), will look for a properties file namedhelloapp_en_US.properties file in the classpath and will load the entries into the helloapp_en_US bundle. Rememberthat since resource bundles are hierarchical, creation of a ResourceBundle triggers the creation of its parent bundle as well.Therefore, once helloapp_en_US bundle is created, its parent bundle helloapp_en would also be created automatically in asimilar fashion. Thus, it will look for helloapp_en.properties to create the helloapp_en bundle. Similarly, since theparent of helloapp_en is helloapp, helloapp.properties will also be loaded.
If, while creating the hierarchy of the resource bundles, at any stage, the getBundle method is not able to find the matchingproperties file, it tries to create the parent bundle of the requested bundle and returns that parent bundle instead. So, ifhelloapp_hi_IN.properties is not available, getBundle("helloapp",  Locale.of("hi", "IN")) methodwill try to create the parent bundle, i.e., helloapp_hi as per the process described above and return this bundle instead.
Effectively, the call to getBundle causes the creation of the hierarchy from the requested bundle up to the base bundle (but not thechildren or siblings) using properties files. The following image illustrates the search path that getBundle takes in this example:
Requesting a resource bundle for the non-default locale ☝
The processing for creating a requested bundle for a non-default locale is almost the same as above. The only difference is that whengetBundle is not able to find any locale specific properties file, it doesn't immediately return the base resource bundle. Beforereturning the base bundle, it tries to find and return the bundle for the default locale. So, for example, let's say the default locale ofthe user is en_US and you request a bundle for hi_IN locale by calling getBundle("helloapp", Locale.of("hi","IN")). Now, if this method is not able to find any properties file that matches hi_IN locale (i.e.helloapp_hi_IN.properties or helloapp_hi.properties), it will try to create and return the bundle for the defaultlocale, i.e., helloapp_en_US. If it is not able to find any properties file for en_US locale either, it will return the base bundle,i.e., helloapp. The following image illustrates the search path that getBundle takes in this example:
At this point, you might be curious to know what happens if getBundle is not able to find any properties file that it can use tocreate any bundle at all. Well, in that case it throws a MissingResourceException. 
The exam does not try to trick you on the location of the properties files. Unless the problem statement statesotherwise, you can safely assume that the properties file given in the question is on the classpath and can beloaded by a ResourceBundle. You just need to check the name of the properties file and the name of the resourcebundle being requested using the getBundle method.
12.3.4 Looking up a key in a ResourceBundle ☝
If you have read the previous two sections carefully, this section will be like a walk in the park. To look up a key in aResourceBundle, you need to first get hold of a ResourceBundle that you are interested in using one of the getBundlemethods and then call one of the following three getXXX methods on that resource bundle:
String getString(String key): Gets a string for the given key from this resource bundle or one of its parents.String[] getStringArray(String key): Gets a string array for the given key from this resource bundle or one of itsparents.Object getObject(String key): Gets an object for the given key from this resource bundle or one of its parents.
Only the first one is important for the exam and you have already seen the example that uses this method earlier. As you must haveobserved in the short descriptions of the above methods, they return a value from this bundle or from one of its parents.
The exam tests you on whether you are able to figure out the value for a key for a non default locale when the keyis not present in the properties file for the non-default locale but is present in the properties file of the default locale.You need to remember that loading a resource bundle and looking up the key in a resource bundle are twoseparate and independent steps. If a properties file for the non-default locale is present, then a resource bundle willbe created using that file as explained in the previous section. The key lookup in the non-default bundle will happenin this non-default bundle hierarchy only and if the key is not found in it, a MissingResourceException will be thrown.The key will NOT be looked up in the resource bundle hierarchy of the default locale. The resource bundle hierarchyof the default locale is used only when no locale specific resource bundle is found.
12.3.5 Formatting Messages using MessageFormat ☝
Showing messages that are grammatically correct in different locales is tricky. For example, a sentence such as "Your balance is 100points." would be grammatically correct in many languages such as English. However, it would be grammatically incorrect in manyother languages such as Hindi, in which the correct form would be, "Your balance 100 points is". Thus, if the program creates thismessage using string concatenation such as String msg = rb.getString("yourbalanceis")+" "+amount+""+rb.getString("points");, the resulting string may look odd in some locales.
The java.text.MessageFormat class can be used to solve this problem. Instead of hardcoding string concatenation, you can
specify parameters in the message string and, at run time, format the string by passing values for those parameters. For example:
ResourceBundle rb = ResourceBundle.getBundle("helloapp"); String message = MessageFormat.format(rb.getString("yourbalanceis"), 100); System.out.println(message); 
The above code uses the static String format(String pattern, Object... arguments) method ofMessageFormat. The value for yourbalanceis key will be Your balance is {0}. inhelloapp_en_us.properties but Your balance {0} is. (but in Hindi, of course) inhelloapp_hi_IN.properties.
Using the MessageFormat class is quite simple. The parameters are specified using curly braces and besides the parameter index(indexing starts with zero), you may specify how you want to format it as well. For example, a raw message could be, "On {0,date, short}, your balance was {1, number, currency}" and it can be formatted using an array of twoobjects as arguments like this: MessageFormat.format(msg, new Object[]{new Date(), 100}); This willreturn "On 10/05/24, your balance was $100.00.".
