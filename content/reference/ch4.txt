4.1 Object-oriented Concepts
4.1.1 Flexible constructor bodies ☝
Java 25 defines an "Early construction context" in JEP 513. This context covers both the argument list of an explicit constructorinvocation (i.e. using super(<args>) and this(<args>)) and any statements that appear before it in the constructor body.Code in an early construction context has the following restrictions:
1. It must not use the instance under construction, except to initialize fields that do not have their own initializers. Thus, code in anearly construction context must not use this, either explicitly or implicitly, to refer to the current instance or access fields orinvoke methods of the current instance.2. It must not use super to access fields or invoke methods of the superclass.
Example:
class Person{ String ssn; //not initialized explicitly int id = 0; //initialized explicitly Person(String s){ ssn=s; //OK because ssn field has no explicit initializer id = 10; //NOT OK because id field has an explicit initializer System.out.println(id+" "+ssn);//NOT OK, can't access fields in EIC super(); } } class Employee extends Person{ int id; Employee(int i){ id = i;//OK because initializing self fields is allowed ssn = "1111" //will not compile because Person's construction is not complete ye super("1234"); //this completes Person's construction ssn = "0000"; //OK because Person's construction is complete } Employee(String s, int i){ id = 20; //OK because initializing self fields is allowed this(i); ssn = "1234"; //OK, usual } } 
4.1.2 Garbage Collection ☝
1. Java code cannot force Garbage collection to happen. It can only request the JVM to perform GC by calling System.gc().2. Circular references (such as A ->B->C->A) do not prevent objects from being GCed. The whole chain will be GCed if thereare no active references to the objects in the program.3. Setting all references to an object to null can make an object eligible for GC but make sure there a reference to the object is notstored in another object.

4.1.4 Record classes ☝
1. Always immutable. Always extends java.lang.Record. Always final. Can implement any interface includingSerializable and Comparable. Can have instance as well as static methods but not abstract or native methods.2. Cannot be abstract, sealed, or unsealed. Cannot define any instance fields but it can have static fields.3. E.g. public record Student(int id, String name, String address){ };
4. A record definition has two parts - record header and record body. Record header specifies the fields and record body is forconstructors and methods. E.g. (int id, String name, String address) is the record header and { } is therecord body.5. The parameters specified in a record header are called record components. Thus, id, name, and address, are thecomponents of the Student record. The compiler turns them into private final instance fields of the same type aka componentfield.6. A record has two types of constructors - canonical and non-canonical. 7. A canonical constructor is the one whose signature is exactly the same as the header. It can be written in normal as well aswell compact form. If a record does not explicitly declare a canonical constructor, the compiler adds it automatically(irrespective of whether there is a non-canonical constructor present or not).8. A non-canonical constructor is the one that takes more or less number of arguments or different types of arguments than theones mentioned in the header. A non-canonical constructor is required to invoke another constructor of the same record in itsbody using the this(<args>) syntax. The chain of constructor invocations must not be recursive. This ensures that thecanonical constructor will ultimately be invoked.9. The canonical constructor must initialize all of the component fields. It has no throws clause and its access modifier is thesame as that of the record.10. A record class without any constructor declarations is automatically given a canonical constructor that assigns all the privatefields to the corresponding arguments of the new expression which instantiated the record.11. A record may have static initializers but not instance initializers.12. Accessor methods: Compiler provides public accessor methods for all of the component fields automatically. The name andthe return type of an accessor method are the same as the name and the type of the field. E.g. int id(), String name(),and String address().13. Accessor method can also be defined explicitly but they must be public and must not have throws clause.14. All records get equals(), hashCode(), and toString() automatically but you can define them explicitly also.15. Important: Remember that nested records (and enums and interfaces) are always implicitly static.

4.1.5 Summary of the application of access modifiers, final, abstract, and static keywords ☝
1. An abstract class doesn't necessarily have to have an abstract method but if a class has an abstract method, it must be declaredabstract. 2. An abstract class cannot be instantiated irrespective of whether it has an abstract method or not.3. A final class or a final method cannot be abstract.4. A final class cannot contain an abstract method but an abstract class may contain a final method.5. A private method is implicitly final. Although it is possible for a subclass to have a method with the same signature as a privatemethod of the superclass, it is not considered an override because final methods are never inherited.6. A private method can never be abstract.7. A static method can be final but can never be abstract.
4.1.6 Sealed types ☝
1. Only classes (both abstract classes as well as concrete classes) and interfaces can be sealed. Enums and Records are alwaysfinal (or implicitly sealed), so, they cannot be marked sealed.2. All direct subclasses of a sealed class must themselves also be declared final, sealed, or non-sealed. 3. Once a class is marked non-sealed, it can be extended by any class without itself being sealed or final.4. All direct subclasses of a sealed class must be listed in the permits clause except when they are defined in the same source file. 5. All direct subclasses of the sealed class must belong to the same package as that of the sealed class except when they are part ofa same named module (in which case, they may belong to different packages). 
Example:
//Account class can have only two subclasses - CheckingAccount and SavingsAccount //CheckingAccount and SavingsAccount must specify whether they are final, non-final, or public sealed class Account permits CheckingAccount, SavingsAccount{ } //Checking account cannot have any subclass because it is final//since it is final, no need to declare its subclasses final class CheckingAccount extends Account{ } //SavingsAccount is sealed and permits only RetirementAccount to extend it sealed class SavingsAccount extends Account permits RetirementAccount{}

4.1.7 Nested types ☝
1. Top level types - All types defined directly within a named or unnamed package.2. Nested types - All types defined inside another type, method, or block.3. Member types - All types whose declaration is directly enclosed in the body of another type. They can be static or instanceand can have any access modifier.4. Local types - Nested types defined within a local scope such as a method or some other code block. Local types cannot haveany access modifier, cannot be explicitly defined as static, and cannot be sealed/non-sealed.5. Anonymous classes - An anonymous class is implicitly declared by a class instance creation expression or by an enum constantthat ends with a class body.6. Inner classes - Any nested class that is not implicitly or explicitly static is an inner class.7. IMPORTANT: All nested interfaces, enums, and records are always implicitly static.
4.1.8 Scopes ☝
1. Java has four visibility scopes, also known as lexical or static scopes, for variables - class, method, block, and flow.2. Java has five dynamic/lifespan scopes for variables - class, instance, method, for loop, and block. Some scopes overlapbecause their visibility and lifespan are the same.3. A variable or a method can be accessed only when it is in lexical as well as lifespan scope.4. Accessing members from a nested type - A nested type is a part of its enclosing type and so, private members of the enclosingtype are accessible inside the nested type.5. Accessing local variables from a local class - A local variable can be accessed from a local class ONLY IF it is final oreffectively final.6. Java 25 adds a new "execution scope" by means of java.lang.ScopedValue API. 
4.1.9 Overloading ☝
1. Same method name but different parameter list. E.g. void m(), void m(int x).2. Names of the formal parameters is not important, only their type matters. E.g. having m(int x) and m(int y) in the sameclass will not compile.3. Return types of the methods do not matter in overloading. They can be the same or different.
Rules for selection of overloaded methods -
1. Exact match - If the compiler finds a method whose parameter list is an exact match to the argument list of the method call, thenit selects that method. E.g. Out of m(Object obj) and m(String str), m(String str) will be invoked if you callm("str") even though m(Object obj) can also accept a String argument.2. Most specific method - If more than one method is capable of accepting a method call and none of them is an exact match, theone that is "most specific" out of all is chosen by the compiler. E.g. out of m(Object obj) and m(CharSequencestr), m(CharSequence str) will be invoked if you call m("str"); because CharSequence is more specific thanObject.3. Consider widening before autoboxing - Higher priority is given to the primitive versions if the argument can be widened tothe method parameter type. E.g. out of m(short value) and m(Byte value), the short version will be picked insteadof the Byte version if you call m( (byte) 1); even though the Byte version is an exact match with byte after autoboxing.4. Consider autoboxing before varargs - If an argument can be autoboxed into a method parameter type then that method will beinvoked even if a method with varargs of the same type is available. E.g. out of m(int... values) and m(Integervalue), the Integer version will be picked if you call m(10).
4.1.10 Overriding ☝
1. Only non-private non-final instance methods can be overridden. 2. It is preferrable to apply @Override annotation to an overriding method.3. Accessibility - An overriding method must not be less accessible than the overridden method.4. Return type - The return type of the overriding method must either be the same as the return type of the overridden method or itmust be a sub type. For example, if the return type of the overridden method is Fruit, then the return type of the overridingmethod can either be Fruit or any subclass of Fruit such as Apple or Mango. This is called the rule of "covariantreturns". In the case of primitive return types, the Java Language Specification mandates that the return type of the overriding methodmust match exactly to the return type of the overridden method.5. Parameters - The list of parameters that the overriding method takes must match exactly to that of the overridden method interms of types and order (parameter names don't matter). 6. Throws clause - An overriding method cannot put a wider checked exception (i.e. a superclass exception) in its throws clausethan the ones present in the throws clause of the overridden method. The overriding method cannot throw a new checked exception that is not listed in the throws clause of the overridden method The overriding method is allowed to omit a throws clause altogether.7. Invoking overridden methods - While determining which method should be invoked, the compiler considers only the declaredtype of the variable on which the method is invoked and the declared type of the variables passed as arguments. At runtime, theJVM picks up the method signature that was selected by the compiler, finds out the actual object pointed to by the referencevariable, and invokes the method on that object. 
4.1.11 Reference type casting ☝
1. The is-a test is used to check whether there is a parent child relationship between two reference types and if there is, which oneof the two types is the parent class, and which one is the child class. E.g. Apple is-a Fruit is always true but Fruit is-a Apple isnot necessarily true. So, Fruit is the parent of Apple. 2. Casting will fail at compile time if the compiler determines that the reference can never point to an object of the type given inthe cast. Casting a variable of a type to a subtype (e.g. casting the variable f of type Fruit to Apple) is called " downcasting" or"narrowing". The opposite of downcasting is "upcasting" or "widening". Downcasting always requires a check by the JVM tomake sure that the variable is really pointing to an object of type that the programmer has claimed it is pointing to. If the checkfails, a java.lang.ClassCastException is thrown. Upcasting does not require any check. 3. Casting to an interface - It is possible to cast any type of reference to any interface except when - 1. the type of the referenceis final and it doesn't implement the given interface, and 2. the type of the reference is sealed and and if it is not possible for anyof its subtypes implement the given interface.
4.1.12 Local variable type inference ☝
1. Used to specify the type of a variable. E.g. var x = 10;. This is also known as var declaration.2. The type of the variable is inferred by the compiler based on the information available in the context. E.g. var x =Math.random(); x will be of type double. Object obj = "hello"; var obj2 = obj; obj2 will be oftype Object and not String.3. Can be used to declare local variables within static as well as instance initializers, constructors, methods, declaration sectionof for loop, and within switch blocks. But the following will cause compilation failure even if defined within a method:var p; //can't use LVTI for uninitialized variablevar n = null; //invalid because type of null can't be determinedvar doubleArray = {1, 2}; //type must be specified in array initializer if usingLVTIvar[] ia = new int[]{1 , 2}; //can't apply [] to var because var is not a type 4. Cannot be used for static or instance fields, for method parameters, or for method return types. 5. LVTI can pick up type information from the generic type arguments that appear in the instantiation of a generic type. But if youinstantiate the generic type using the diamond operator, for example, var list = new ArrayList<>();, LVTI will
infer the type argument to be Object.6. LVTI can be used while declaring variables in a lambda expression. E.g. (var a) -> a*a. Parentheses are required if youare using var.
4.1.13 Unnamed Variables ☝
1. An unnamed variable is declared using an underscore character, i.e., _. E.g. int _ = 10;2. You can assign it a value but you cannot access/read it. E.g. print(_); //will not compile3. Can be used only within a locally scoped code block. 4. Can be used any number of times.5. Can be used to declared unused pattern variables in switch and instanceof.6. Not allowed for static or instance fields. 7. Not allowed for method parameters.
4.1.14 Interfaces ☝
1. Always implicitly abstract, always implicitly public (even when nested).2. All fields defined in an interface are implicitly public, static, and final.3. Can have 4 types of methods - abstract methods (always public), static methods (can be private or public but not protected),default methods (always public), and private methods.4. Static methods of an interface are not inherited (unlike static methods of a class), meaning, you cannot invoke a static methodof an interface using a reference variable of an implementing class or using the name of the class.5. Fields of an interface are inherited by the implementing class, meaning they can be accessed using the name of class. Javaallows a class to inherit multiple fields with the same name as long as you don't try to use those fields ambiguously.6. Inheritance of multiple versions of a default method - if a class inherits multiple implementations of a default method (becauseit implements multiple interfaces containing the same default method), then the class must override that method.7. When a class inherits a method from its superclass and also from an interface that it implements, the version that it inherits froma superclass overrides the default method defined in any of the interfaces that it implements, the version that it inherits from asuperclass overrides the default method.
4.1.15 Functional interface ☝
1. Any interface that has exactly one abstract method is a functional interface. It may have other private, static, or default methodsbut it must have one and only one abstract method. This abstract method is also called the "functional method" of thatfunctional interface.2. A functional interface is usually annotated with @FunctionalInterface but it is not necessary. 3. A method that implements an interface method must follow the same rules as an overriding method. The return type mustbe covariant with the return type declared by the interface. The parameter list must be an exact match (except the names of theparameters). The throws clause must be compatible with the throws clause of the interface method.4. Java SDK provides several readymade functional interfaces in java.util.function package. Check out the JavaDoc forthese: Predicate, Function, Consumer, Supplier, BiFunction, and, UnaryOperator.5. Identity function - java.util.function.Function contains an idenity() method. It returns a Function objectwhose functional method returns the same value as the one that is passed to it.
4.2 Scoped values ☝
1. A better alternative than thread-local variables due to lower space and time costs.
2. A scoped value is a container object that allows a data value to be safely and efficiently shared by a method with its direct andindirect callees within the same thread, and with child threads, without resorting to method parameters. 3. It is a variable of type java.lang.ScopedValue and is typically declared as a private static final field.4. Like a thread-local variable, a scoped value has multiple values associated with it, one per thread. The particular value that isused depends on which thread calls its methods.5. Unlike a thread-local variable, a scoped value is written once, and is available only for a bounded period during execution ofthe thread.6. Bindings are per-thread : A new thread spawned from the current thread does not automatically get access to the scoped value.7. Scopes can be nested and a scoped value can be rebound to a new value for the nested scope.
Example:
final static ScopedValue<String> SC = ScopedValue.newInstance(); public static void main(String[] args) { System.out.println(SC.isBound());//prints false ScopedValue .where(SC, "A") //SC is bound to A inside run .run(()-> { System.out.println(SC.get()); //prints A ScopedValue.where(SC, "B").run( //SC is rebound to B ()->System.out.println(SC.get()) //prints B ); //nested scope ends System.out.println(SC.get());//prints A } ); //SC is back to unbound from here System.out.println(SC.isBound());//prints false System.out.println(SC.orElse("UNK")); //prints UNK System.out.println(SC.get()); //throws java.util.NoSuchElementException System.out.println(NAME.orElseThrow(Exception:new)); //throws Exception }

1. static <T> ScopedValue<T> newInstance() : Creates a scoped value that is initially unbound for all threads.2. static <T> ScopedValue.Carrier where(ScopedValue<T> key, T value): Creates a new Carrierwith a single mapping of a ScopedValue key to a value.3. T get() : Returns the value of the scoped value if bound in the current thread. Throwsjava.util.NameNotFoundException if value is unbound.4. boolean isBound() : Returns true if this scoped value is bound in the current thread.5. T orElse(T other) : Returns the value of this scoped value if bound in the current thread, otherwise returns other.6. <X extends Throwable> T orElseThrow(Supplier<? extends X> exceptionSupplier): Returnsthe value of this scoped value if bound in the current thread, otherwise throws an exception produced by the exceptionsupplying function.
ScopedValue.Carrier API
1. <R, X extends Throwable> R call(ScopedValue.CallableOp<? extends R, X> op) : Calls avalue-returning operation with each scoped value in this mapping bound to its value in the current thread.2. <T> T get(ScopedValue<T> key) : Returns the value of a ScopedValue in this mapping.3. void run(Runnable op) : Runs an operation with each scoped value in this mapping bound to its value in the currentthread.4. <T> ScopedValue.Carrier where(ScopedValue<T> key, T value) : Returns a new Carrier with themappings from this carrier plus a new mapping from key to value.
